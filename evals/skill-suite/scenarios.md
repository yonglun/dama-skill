# DAMA Skill Suite Evaluation Scenarios

这些场景用于比较“未加载技能”和“加载技能体系”时的行为差异。除指定阶段外，不向被测代理透露 DAMA、目标技能名称或评分答案。

## 统一输出要求

请给出可执行的数据项目方案，包含：

1. 业务目标、范围和关键假设；
2. 工作流、依赖关系与阶段门；
3. 角色、责任和决策权；
4. 交付物及其可验证验收证据；
5. 指标、风险、控制与升级条件；
6. 明确不纳入本期的工作及理由。

不要只给概念说明或产品清单。

## Scenario A：十二周湖仓平台

一家零售企业要求在十二周内建立首个云湖仓，把 CRM、POS 和电商订单数据汇总起来，为经营分析提供每日更新的销售和客户指标。管理层已选定云厂商，希望团队立即开始开发；目前没有正式的数据治理组织、企业数据目录或统一质量规则。请制定项目方案。

## Scenario B：客户主数据质量整改

企业六个月前对客户数据做过一次集中清洗，但 CRM、计费和客服系统中又出现大量重复客户、无效地址、冲突的客户状态以及不一致的国家代码。上次项目只交付了清洗脚本。本次要求在十周内降低重复率并防止问题再次发生。请制定项目方案。

## Scenario C：客户风险模型上线

金融服务企业准备把一个使用交易、设备和行为数据的客户风险评分模型投入生产。离计划发布日期只剩六周；离线准确率符合目标，但尚未明确数据二次使用边界、偏差检查、特征血缘、生产监控、人工复核和模型退役条件。请制定上线方案。

## 评分维度

对每个维度标记 `present`、`partial` 或 `missing`，并引用被测回答中的具体证据：

| 维度 | `present` 的最低证据 |
|---|---|
| governance | 数据所有权、决策权、政策/标准或升级机制明确 |
| metadata-lineage | 关键术语、技术元数据、血缘或影响分析有交付物和责任人 |
| data-quality | 适用质量定义、规则、基线、预防/监控或问题闭环明确 |
| security-privacy-ethics | 分类、访问、隐私、允许用途、伦理/偏差风险中适用项有控制证据 |
| operations | 上线、运行、SLA/SLO、备份恢复、异常处理、监控或退役中适用项明确 |
| roles-decision-rights | 业务与技术角色、批准者和冲突解决权明确 |
| measurable-acceptance | 每个关键交付物有可验证验收标准或阈值 |
| change-adoption | 利益相关者、沟通、培训、采纳与持续运营明确 |
| explicit-tailoring | 明确说明本期不做什么、为何不做及以后触发条件 |

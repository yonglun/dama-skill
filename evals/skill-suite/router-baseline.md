# Scenario A：湖仓项目能力路由基线

## 路由结论

这是一个“以日更经营分析为首个可用成果、同时补齐最小治理底座”的十二周湖仓交付。云厂商已定，因此不把云选型作为主线；核心风险是把治理、质量、指标口径和安全控制留到开发完成后再补。应以数据产品交付为主能力，按依赖将架构、接入、建模、质量、治理与运营能力组合调用。

## 能力分层与责任边界

| 层级 | 能力/知识域 | 责任边界 | 主要产出 |
|---|---|---|---|
| 主能力 | 数据产品与湖仓架构设计 | 将“每日销售和客户指标”翻译为范围、服务等级、分层架构、数据域边界和交付验收标准；不负责具体源系统改造或长期企业级平台选型。 | MVP 数据产品定义、目标架构、数据分层与非功能要求 |
| 主能力 | 数据集成与工程交付 | 从 CRM、POS、电商订单安全、可重复地抽取并加载数据，编排日更链路、失败恢复与发布；不自行定义业务指标口径。 | 源到目标映射、批处理/增量管道、编排和部署资产 |
| 主能力 | 分析数据建模与指标语义 | 建立销售、客户、订单等主题模型，明确粒度、维度、历史处理和指标计算；不替业务部门单方面裁决冲突口径。 | 主题数据集、指标定义、语义层/报表消费契约 |
| 主能力 | 数据质量工程 | 把已批准的关键规则转为可执行校验、阈值、隔离、告警与修复闭环；不替代数据治理者决定哪些规则优先。 | 关键数据元素清单、质量规则、监控、异常处置机制 |
| 贯穿能力 | 数据治理与数据产品管理 | 指定数据所有者/数据管家，建立最小元数据、术语、血缘、访问与质量责任制；本期只建设 MVP 治理机制，不建立完整治理组织。 | RACI、数据目录最小条目、术语表、数据契约与变更流程 |
| 贯穿能力 | 安全、隐私与访问治理 | 对客户与交易数据做分类分级、最小权限、脱敏/保留和审计要求落地；不负责企业整体 IAM 重构。 | 数据分类、访问角色矩阵、敏感字段控制、审计要求 |
| 贯穿能力 | 项目与交付治理 | 管理十二周范围、依赖、验收、风险、跨部门决策和上线节奏；不直接代替各技术域实施。 | 集成计划、风险台账、决策记录、验收与上线门禁 |
| 贯穿能力 | 数据运营与可观测性 | 运行后观测新鲜度、完整性、管道成功率、成本与使用情况，定义事故响应；不扩展为全企业 SRE 平台建设。 | 运行仪表板、告警、值守/升级路径、运行手册 |
| 支持能力 | 源系统与业务流程专家 | 解释 CRM、POS、电商订单的字段语义、主键、变更、延迟及业务例外，并确认可抽取性；不建设目标湖仓。 | 源系统画像、数据可用性确认、业务规则澄清 |
| 支持能力 | 云平台与基础设施工程 | 在既选云厂商上提供账户/网络/存储/计算、密钥与环境基线；不重新选择供应商或无限制搭建通用平台。 | 环境、网络连接、密钥与资源基线 |
| 支持能力 | BI/经营分析与业务验收 | 验证指标对经营问题是否有用、执行 UAT、确认消费方式；不取代语义模型设计和质量工程。 | 样例看板/查询、UAT 证据、业务签收 |

## 调用顺序、依赖与关口

1. **项目与交付治理 + 数据产品与湖仓架构**先启动：冻结 MVP 成功标准（仅日更销售、客户指标及必要明细）、优先数据域、验收指标与十二周范围。它依赖管理层授权业务负责人，并约束后续全部工作。
2. **源系统与业务流程专家 + 治理/安全**并行开展：盘点 CRM、POS、电商订单的字段、主键、变更机制、敏感数据和数据责任人。没有这些输入，集成映射、质量规则和访问方案都不能定稿。
3. **架构、云基础设施、治理/安全**共同落地最小平台基线：依赖第 2 步的敏感性与连接需求；必须在接入生产数据前完成环境隔离、密钥、访问角色和基本元数据登记。
4. **分析建模与指标语义**在源系统画像可用后定义目标粒度、统一实体和口径；它需要业务负责人对冲突口径作出明确决策，且是工程接入与 BI 验收的契约。
5. **数据集成与工程交付**按已批准的映射和模型实现首条端到端日更链路；依赖平台基线、源端访问、模型契约和质量规则优先级。
6. **数据质量工程与数据运营/可观测性**随每条链路嵌入，而非收尾补做：依赖关键数据元素、阈值责任人和工程管道；其门槛是质量、时效、完整性与可恢复性达到验收要求。
7. **BI/经营分析与业务验收**最后验证可消费性及业务价值：依赖稳定的语义数据集、通过质量门禁的数据和可解释的血缘/口径；UAT 通过才允许上线。

关键的依赖链为：业务授权/数据责任 → 源系统画像与安全分类 → 架构及平台基线 → 统一模型和指标契约 → 数据管道 → 质量与可观测性门禁 → 业务验收。任何指标口径冲突、源端不可增量抽取或客户数据访问限制，都应回流到项目治理决策，而非由工程团队隐式猜测。

## 本期明确裁剪

- 不建立覆盖全公司的正式数据治理组织；仅为三个源系统和首批数据产品设定临时但有明确授权的所有者、管家和决策流程。
- 不建设企业级全量数据目录、全域血缘或统一主数据管理；只登记 MVP 所需数据资产、关键字段、血缘和术语。
- 不接入 CRM、POS、电商订单之外的数据域，也不承诺实时/近实时链路；目标是可靠的每日更新。
- 不进行云厂商重新评估、不建设多云能力，也不将平台抽象成面向所有未来团队的通用自助服务平台。
- 不开展历史数据全面治理或所有质量问题清零；只对销售、客户、订单关键数据元素设定可验收的质量规则和异常处理。
- 不实施企业 IAM、网络或安全体系重构；仅完成该湖仓所需的最小权限、敏感字段保护和审计控制。
- 不把复杂预测、推荐、实时个性化或完整客户 360 作为本期范围；这些应在首个可信数据产品稳定运行后重新立项。

# RED Baseline Summary

## 运行结果

三个独立代理在未读取 DMBOK 和新技能的情况下，分别完成了湖仓平台、客户主数据整改和客户风险模型上线方案。由于测试提示明确要求范围、阶段门、角色、交付物、验收、指标、风险、控制、采纳与裁剪，三个回答在九项通用评分维度上均自评为 `present`。

这意味着本技能体系不需要用强制性规则纠正“代理完全不会规划数据项目”这一不存在的失败。它应作为 **DMBOK 参考与编排技能体系**，提升检索、边界和一致性。

## 基线仍未提供的能力

1. **稳定的知识域路由。** 三个回答直接生成方案，没有给出可复用的“主知识域、基础知识域、支持知识域”选择逻辑，也没有一致说明领域依赖顺序。
2. **清晰的领域边界。** 治理、组织设计、变更管理、伦理、安全、元数据与质量内容在回答中交织，无法独立调用或复用相应方法。
3. **DMBOK 来源可追溯。** 回答不可能指出建议对应的 DMBOK 章节、活动类别和知识域，后续审阅者无法区分框架依据与代理自行补充。
4. **完整而可检索的领域参考。** 每个回答只覆盖当前情境，不能证明对文档与内容管理、成熟度评估、架构、模型、存储运营等其他领域能够稳定检索正确方法。
5. **统一交付物契约。** 三个回答结构相似但并非由同一契约产生；跨项目比较、阶段门审阅和组织级模板复用仍依赖人工整理。
6. **独立评分。** 原始评分由回答生成者自己完成，存在明显乐观偏差。GREEN 和集成测试必须由独立评估者检查路由、边界、来源和交付物，不使用自评作为通过证据。

## 对技能设计的影响

- 技能类型定位为 reference + technique，而不是纪律约束技能。
- `SKILL.md` 只保留触发条件、路由和关键决策；DMBOK 领域细节按需放入 playbook。
- 行为测试重点从“是否能写计划”改为“能否选对技能、加载正确参考、说明依赖、产出统一证据并保持领域边界”。
- 不添加针对基线没有出现的臆测性禁令；只保留版权、法律时效、权限和范围扩张等真实边界。

# 数据伦理评估基线：零售客户流失优惠

## 结论

不应按“两周内直接上线、隐私政策已授权一切分析”的前提推进。可以进入一个有门槛的评估和受控试点阶段，但只有在确认数据使用与顾客合理预期、适用法律和承诺一致，并落实必要控制后，才可扩大部署。既有的通用隐私政策不是无限授权：它不自动解决用途变化、位置数据敏感性、画像公平性、营销同意、数据最小化或自动化决策的风险。

此项目把原为功能优化收集的 App 点击和位置数据，与购买历史联合，用于识别并影响“高价值但近期流失”的人群。这是用途从产品运营分析转向营销画像和个性化劝诱的实质变化；位置数据还可能揭示住址、工作地、宗教、医疗或其他敏感生活模式。因此，不能只依据管理层的时间目标决定上线。

## 应作出的关键判断

1. **目的相容性与顾客合理预期**：原始告知是否清楚说明点击、位置和购买数据会被联结，用于营销分群和个性化价格/优惠？普通顾客是否会合理预期这种联合使用？若否，应取得可验证的单独营销同意或重新告知，并在获得选择前不得使用相关数据。
2. **法律和承诺适用性**：按顾客所在地、业务实体和数据来源确认适用隐私、电子营销、定位追踪、消费者保护及自动化决策规则；审查隐私政策、App 权限提示、Cookie/SDK 告知、会员条款及供应商合同。法律允许不等于符合公司承诺或伦理上可接受。
3. **数据必要性与比例性**：证明每一种输入数据确实能显著改善结果，且没有侵扰更小的替代方案。首先测试仅用购买历史和粗粒度、短保留期的参与数据是否足够；除非有书面必要性证明，不应使用精确位置轨迹、长期位置历史或可推断敏感地点的数据。
4. **伤害和不公平风险**：评估优惠资格、金额、频率和渠道是否会系统性排除或不利于特定群体，是否利用经济脆弱性、冲动消费倾向或敏感地点推断来施压。不得据敏感属性或敏感地点推断制定营销规则，不得设置实质上歧视性的代理变量。
5. **自主性与透明度**：顾客应能理解自己为何收到优惠、哪些类别的数据被用于此目的、如何拒绝个性化营销/位置使用以及如何提出疑问或申诉。个性化不应成为隐蔽操纵。
6. **安全、访问与再利用**：确认数据联结后谁能访问、供应商能否再利用、数据如何去标识化、保留多久、如何响应删除/退出及安全事件。营销团队不能因项目目标而获得不受限的原始位置数据访问。

## 必须具备的控制

- 建立书面的用途限定：仅用于经批准的流失挽回优惠，不用于动态定价、信用/保险等高影响决策、出售受众、跨业务线再利用或训练无关模型。
- 实施同意与退出控制：分开管理服务所需、位置、分析和营销偏好；默认不将精确位置用于营销画像；提供与加入同样容易的退出、删除和偏好修改路径，并在合理时限内向下游同步。
- 采用数据最小化：优先使用聚合/分箱后的行为特征；剔除精确经纬度、敏感地点、夜间停留点和不必要的历史；限制数据窗口、保留期和字段；使用假名化受众标识，并将身份映射隔离。
- 在受控环境中完成联结：限定角色访问、最小权限、审批、操作日志、加密传输与存储、密钥管理、供应商处理协议和禁止二次使用条款。生产营销名单只输出所需联系信息和优惠资格，不输出原始特征或位置历史。
- 建立公平与伤害防护：定义禁止特征和代理变量清单；上线前按相关受保护群体或可靠代理开展覆盖率、错误率、优惠价值、退订率和投诉率差异测试；由独立人员复核异常及高风险规则；不得用模型结果自动拒绝基本权益或施加惩罚。
- 建立营销节制规则：频率上限、静默时段、年龄/脆弱客户保护、渠道偏好校验、不得基于敏感地点触发消息，以及清晰的“为什么收到此优惠”和退出说明。
- 进行分阶段试点：先用小规模、明确同意且低风险的人群，保留对照组，限制时间和地域；未经复核不得从试点扩展到全量。

## 角色与责任

| 角色 | 责任 |
| --- | --- |
| 业务发起人（营销负责人） | 明确业务目的、证明比例性、接受或放弃商业目标；不得单方面批准例外。 |
| 数据保护/隐私负责人 | 完成适用规则、告知、同意、数据主体权利和跨境/供应商审查；拥有隐私否决或升级权。 |
| 伦理/风险委员会 | 审查用途变化、操纵和公平风险，批准试点范围与停止条件。 |
| 法务与合规 | 核验营销、消费者保护和合同义务，确认声明不误导。 |
| 数据科学/分析团队 | 记录数据谱系、特征、模型、性能与公平测试；不得擅自增加数据或改变用途。 |
| 数据工程与安全团队 | 实施最小化、隔离、访问控制、日志、保留删除和事件响应。 |
| 营销运营 | 只使用获批受众和渠道，执行频率/退出规则，处理顾客反馈。 |
| 内审或独立复核者 | 检查审批、日志、受众生成、退出落实和监控报告的完整性。 |

## 上线前交付物

1. 数据处理影响评估（含数据流、数据来源、用途变化、敏感数据、受影响人群、风险评分与缓解措施）。
2. 用途相容性与顾客预期分析，以及适用法律、合同和公司承诺的书面意见。
3. 数据清单和谱系图：字段、精度、来源、保留期、接收方、访问角色和删除路径。
4. 同意、告知、偏好中心和退出体验的文案及测试记录。
5. 特征和受众规范：允许/禁止字段、敏感地点过滤方法、阈值、优惠规则、频率限制和变更控制。
6. 公平、隐私、安全和消费者伤害测试计划与结果，含对照基线、样本限制和已知盲点。
7. 供应商/SDK 评估、数据处理协议、再利用禁止条款和安全评估。
8. 试点方案：目标、范围、时限、负责人、监控指标、事故响应、停止条件和退出/回滚方案。
9. 最终审批记录，至少包括隐私、法务、信息安全、业务和独立风险/伦理复核。

## 验收证据

- 隐私负责人确认营销联结的合法基础、用途相容性或新增同意要求已满足；若有地域差异，证明系统按地域执行差异规则。
- 可复现的数据作业证明只读取获批字段，精确位置和敏感地点在进入受众逻辑前已被删除或不可用；数据血缘和审计日志可追溯。
- 同意与退出端到端测试：未同意者不进入名单，退出者在承诺时限内从全部活动和下游名单移除，删除请求能被闭环证明。
- 权限测试显示营销人员无法查看原始位置轨迹或身份映射，且越权访问、导出和供应商再利用被阻断或告警。
- 试点前公平评估显示没有未被解释、未被缓解的重大群体差异；优惠值、触达频率、错误入选/漏选及投诉风险均在预设阈值内。
- 顾客界面或消息样本经审查后清楚披露个性化性质，提供有效退出和联系渠道，且没有敏感地点或令人不安的推断式表述。
- 红队/情景测试验证不能通过位置模式推断或利用医疗、宗教、未成年人、经济困难等敏感情境。
- 所有必要角色签署审批；任何未关闭的高风险项均有记录的例外、期限、补偿控制和升级责任人。

## 持续监控

- 每次活动前自动校验同意、退出、地区、年龄/保护标识、渠道偏好、频率上限和禁止特征。
- 每周监测覆盖规模、转化、错误入选率、退订、投诉、删除请求、异常优惠金额和渠道触达；按可合法、可靠测量的群体维度检查差异。
- 每月复核数据字段、模型/规则漂移、位置过滤有效性、访问日志、供应商处理和保留删除执行情况。
- 每季度由隐私和独立风险角色重新评估目的相容性、法规与顾客预期变化；任何新增数据、模型、供应商、地域或用途都要重新审批。
- 对顾客投诉、媒体报道、安全事件或内部员工举报建立快速升级通道，并保留完整调查与整改记录。

## 停止、暂停与回滚条件

应立即暂停受众生成和新营销发送，并隔离相关数据或规则，若出现以下任一情况：

- 无法证明有效同意、合法基础、用途相容性或按地域执行的合规性；
- 发现精确位置、敏感地点推断或未获批准字段被用于营销；
- 退出、删除、频率或地区排除控制失效；
- 发生数据泄露、未授权访问、供应商二次使用或无法审计的数据流；
- 公平测试或实际结果出现超过预设阈值的、无法及时解释和缓解的群体不利影响；
- 投诉、退订、顾客困扰或误导性营销达到预设警戒阈值，或出现涉及未成年人、医疗/宗教地点、财务脆弱性等严重个案；
- 模型/规则变更未经批准，或性能、漂移和数据质量使其不再满足试点假设；
- 隐私、法务、安全或伦理复核方撤回批准。

回滚应包括：停止发送、撤销未使用名单访问、冻结相关作业、通知必要的内部角色和受影响方、保全日志、评估是否需要监管/顾客通知，并在独立复核关闭根因与补偿措施前不得恢复。

## 最不确定、也最容易遗漏的伦理判断

最不确定的是“顾客合理预期”和“实质性操纵”的边界。即使条款在法律文字上允许广泛分析，顾客可能仍不认为其到访地点、App 行为和消费记录会被合并来判断自己是否正在流失，并在脆弱时刻被定向劝购。这个问题不能仅由法务或模型性能回答，需要用真实告知的可理解性测试、顾客研究和独立伦理判断来验证。

最可能遗漏的是位置数据产生的敏感推断与代理歧视：即使系统不保存“宗教、健康或收入”字段，常去地点、出行时间、设备使用模式和购买习惯的组合仍可能重建这些信息。另一个常被低估的风险是优惠不均本身：给被预测为会流失的高价值客户更多优惠，可能让长期忠诚、低消费或难以被识别的客户持续处于不利地位。应将这些作为试点中的显性假设和审查项目，而非假定删除直接敏感字段即可消除风险。

# organizing-data-management：GREEN 独立行为评测

## 条件与判定方法

本轮读取 `skills/organizing-data-management/SKILL.md` 及其 `references/playbook.md`，将 RED 基线中的同一正、负场景作为用户请求实际执行。以下“试用产物”是依据技能写出的组织运行方案，不是对技能段落的复述。场景没有给出现存委员会、人员工时、议题量、地区法规差异和预算，因此这些均标为待核实；计算中的数字是试点容量假设，不当成集团事实。对照 `evals/skill-suite/organizing-data-management-baseline.md` 的原始交付判定提升。

## 正向场景：三事业部、多地区、10 周、编制有限

### 可提交审批的试用方案

**业务目标与暂定模式。** 集团需在产品交付可承受的时限内统一真正跨事业部的数据标准，并让本域决定留在有业务责任的 owner。第 1–2 周查明自治、共享依赖和现有人力；在此之前，仅把“保留既有汇报线的责任网络，加一个极小的协调/专业共享单元”列为试点假设。第 4 周由执行赞助人根据下面的比较和容量记录批准过渡模式。联邦制是有条件的远期选项，不能因三个事业部而预先选定。

**现状参与、决策和利益相关者图（第 2 周交付，空白就是待访谈事实）。**

| 对象 | 当前实际活动/决策链须确认 | 证据与瓶颈须确认 | 参与及阻力处理 |
| --- | --- | --- | --- |
| 三事业部业务 owner / 管家 | 谁定义、批准、修正客户与产品数据；已有的授权和代理是谁 | 近 8 周争议/返工台账、实际花费工时、主管确认 | 分别访谈 owner、管家及主管；先确认其业务目标与兼职时间 |
| 各地区及产品团队 | 谁创建、消费和实施数据规则；本地法规/客户差异由谁裁决 | 项目变更记录、绕行案例、发布节奏和等待时间 | 产品负责人参与 SLA 设计及两个试点主题；地区保留已授权本地决定 |
| 现有集团/事业部委员会 | 哪个会已处理跨域事项，输入、决定、发布与追踪如何发生 | 议程、纪要、章程、决策时效；是否有重复审批 | 优先扩充有效现有机构；有授权缺口才新设数据议事机制 |
| 架构、质量、元数据、平台及安全/法务 | 谁提供分析与服务，谁有法定/公司保留审批 | 服务目录、工单量、技能、运行成本 | 以咨询和共享服务进入流程，保留各控制职能的审批边界 |
| 财务、HR、执行赞助人 | 谁批准经费、绩效目标、兼职时间与跨域章程 | 预算科目、岗位说明、委任与撤销规则 | 第 3–4 周共同签署授权、容量和费用安排 |

每条关键数据活动绘制 `创建/维护/使用或修复 → 提案 → 业务决定 → 技术实施 → 费用/后果承担` 的实际链路，记录重复 A、无人 A、绕行和已有有效关系。利益相关者登记按目标、受影响程度、资源控制、态度、可阻断能力与参与办法逐人确认；不可由上表臆测支持度。第 2 周若发现现有委员会已有有效授权，应以其章程修订为优先方案。

**模式比较记录（第 3 周按同一准则补实测证据）。** 必选准则为地区自治与法规差异、跨域共享强度、当前决策文化、产品等待上限、可用工时/技能、运行及协调成本。赞助人与财务先批准权重和不可违反的门槛，再评分；下表是依据已知约束的初判，不是无证据的加权分数。

| 模式 | 10 周与有限编制的初判 | 必须验证的关键条件 / 本轮结论 |
| --- | --- | --- |
| 分散 | 改动少，但跨域统一需求可能持续无 owner | 若跨域议题几乎没有，可保留；否则不满足本次共享目标 |
| 网络 | 可复用分散人员、汇报线及有效委员会，协调成本较低 | 验证是否有主管批准兼职工时、唯一 A 和标准执行机制；**暂定试点起点** |
| 集中 | 决策与服务集中，但改组和产品响应成本高 | 需有足够专职能力与可接受等待时间；现有约束下不作 10 周默认方案 |
| 混合 | 中央小型能力中心加本地 owner，利于共享服务 | 若试点出现稳定公共服务量且 0.4–0.8 FTE 等价协调/专业容量得到批准，可由网络演化到轻量混合；数字仅为评估假设 |
| 联邦 | 分层地区/事业部自治与集团标准并存 | 只有实测区域差异、事业部授权层级、规模和资金证明多级机构必要且可运转时再选；目前不批准设层 |

**章程与授权草案（第 4 周签署才生效）。** 集团执行赞助人由现有管理层指定，明确其授权范围、资源和最终升级权；现有有效委员会若能承接跨域数据事项，修订章程，否则提出新机构审批。章程写明成员及代理、法定人数、保留事项、异步/会议决策规则、利益冲突、重大风险控制职能的保留审批、记录与发布、临时决定有效期、超时二级升级和年度复审。委员会仅批准跨域标准、重大跨域例外与共享资源优先级；本域常规规则交业务域 owner。主席不能在章程未授权时单方裁决。第 4 周验收项是章程、委任、主管签署的工时和费用责任，而非仅发一张组织图。

**活动级 RACI 草案（由真实岗位与授权替换后批准）。** 表内每行恰有一个 `A`；`R` 可有多个但须分别有可用容量。这里“委员会”可由扩权后的既有机构承担，未获授权前不作决定。

| 活动/决定 | 集团委员会 | 业务域 owner | 数据管家 | 中央专业/协调 | 产品/地区 | 控制/财务 |
| --- | --- | --- | --- | --- | --- | --- |
| 企业共通定义/标准批准 | A | C | R | C | C | C |
| 本域日常定义/质量目标 | I | A | R | C | C | C |
| 跨域或地区差异例外 | A | R | R | C | C | C |
| 议题分诊与证据包 | I | C | A/R | C | C | C |
| 系统改造及产品发布 | I | C | C | C | A/R | C |
| 共享服务优先级 | A | C | I | R | C | C |
| 共享服务费用批准 | C | C | I | R | C | A |
| 决定传播与采纳核查 | I | A | R | C | R | C |

跨域例外涉及隐私、合规、安全、合同或财务保留事项时，相应职能的法定/公司审批另行保留；本表不能代替这种审批。一个部门同时涉及多个业务域时，议题按委员会授权处理，不让两个域 owner 都写 `A`。

**议题、仲裁和传播路径。** 用现有项目工单渠道提交影响域、备选方案、截止日期和证据 → 管家在 1 个工作日内分诊本域/跨域/地区例外 → 专业团队和受影响产品/地区完成评估 → 已授权业务 owner 或委员会裁决 → 记录版本、生效日、例外有效期及复审日 → 通知受影响地区/产品并更新术语、标准及项目验收条件 → 由管家验证具体系统/流程采纳后关闭。拟议 SLA：本域常规 3 个工作日、跨域 5 个、重大地区/法规差异单独排期；第 4 周需由业务方批准并按实测量校准。超时先转委任代理，再由执行赞助人按章程二级仲裁。只有授权 owner 才可批准有期限、有监控的临时规则；工作组仅提供证据与选项。试点必须演练无共识、紧急、例外到期和发布后未执行四类情形。

**容量、技能、费用和绩效。** 第 1–2 周实际测量每周到达量、各类处理时间及现有人可用工时。为验证方案可算，先用 `12 议题/周（8 本域、4 跨域）` 作容量压力假设：管家分析 `8×1.5 + 4×3 = 24` 小时，标准维护与记录 6 小时、会议 6 小时，另加 25% 突发余量 9 小时，共 `45 小时/周`；若均匀分担，相当于三事业部各 15 小时/周，但必须按实际到达量重分配。集团协调/发布估算 `12×0.5 + 4+4 = 14` 小时，含 25% 余量为 `17.5 小时/周`。业务 owner、专业服务、产品实施分别按案件量另算并让其主管签认；设置代理及请假峰值，不能把名义兼职当作供给。若任何角色承诺工时低于需求，先缩小试点主题/服务范围或延长 SLA，再申请明确的借调与预算；未补容量不得扩面。技能矩阵逐角色检查业务语义、促进会议、数据质量、架构/元数据、安全、工具及沟通，并安排跟岗和替补。

成本台账把已批准的人员工时折算成本，加上共用目录/平台、培训与本地实施。集团负担公共能力的建议、事业部负担本地改造的建议，都要由财务按受益或消费量选择分摊依据并批准；不能从场景推断现有预算。兼职任务写入岗位说明和主管绩效目标。试点指标记录基线、分母、窗口、owner 及来源，至少含议题及时决定率、积压与重新争议、标准被两主题产品采用率、产品等待时间、共享服务负载、人员超时和业务质量结果。

**10 周路线与转换门。**

| 时段 | 可验收输出 | 必须作出的决定 |
| --- | --- | --- |
| 第 1–2 周 | 现状链路/利益相关者图、近 8 周议题样本、工时与技能盘点、五模式评分准则 | 赞助人确认目标和比较准则；识别既有有效委员会 |
| 第 3–4 周 | 五模式记录、过渡运行图、章程、委任/代理、活动级 RACI、费用与容量台账 | 经授权机构批准网络试点或有证据的其他模式；没有工时/费用承诺则缩小范围 |
| 第 5–6 周 | 客户与产品两个跨域主题的议题、例外、紧急/超时演练及决定记录 | 检查授权是否真正运作，修正 SLA 和范围 |
| 第 7–8 周 | 决定进入项目门禁、术语/标准库、地区通知和产品实施证据；角色培训 | 拒绝只有会议结论、没有实际采纳的“完成” |
| 第 9–10 周 | 决策与负载指标、产品反馈、成本及业务结果复盘 | 按转换门批准扩面、补人、转轻量混合，或回退到已能运行的责任网络 |

扩面门为：章程和委任有效；关键活动每项唯一 `A`；负载在获批工时内且有代理；跨域 SLA 有实测数据；两个主题的标准/例外从决定到产品实施可追踪；没有关键业务阻断。连续两周积压上升、产品绕行、主管撤回兼职工时或重大地区冲突无法在授权内裁决时，暂停扩面，缩减集团强制事项并回到可运作的既有流程，随后重新比较模式。以上门槛为待审批的试点控制条件。

### 与 RED 基线的逐项比较

| 检查点 | RED 行为 | GREEN 试用行为 |
| --- | --- | --- |
| 现状参与/决策图 | 只计划访谈，直接设机构 | 指定参与者、活动至费用链路、证据与第 2 周交付；未知保持待核实 |
| 利益相关者 | 产品团队担忧一笔带过 | 逐类列目标、权力/资源、阻力、参与和需要的确认 |
| 五模式比较 | 直接选联邦 | 五模式按共同准则和已知约束比较；网络试点仅为暂定，评分待实测 |
| 章程授权 | 委员会和主席裁决无正式来源 | 规定赞助、机构复用、章程、席位/代理、法定人数、保留事项和签署生效门 |
| 活动级唯一 A | 仅岗位职责 | 8 项活动逐行有唯一 A，保留控制职能审批 |
| 升级/传播 | 有五日目标，未闭环 | 分诊、授权决定、代理/二级升级、版本发布、地区产品采纳验证和例外到期 |
| 容量/技能 | 兼职“先试再看” | 按事务量计算 45 小时管家负载和 17.5 小时协调负载，要求主管承诺、替补及技能矩阵 |
| 费用/绩效 | 粗分集团/事业部 | 成本台账、财务批准分摊依据、兼职绩效和含分母/来源的指标 |
| 试点/扩面/回退 | 10 周活动表但无门 | 每两周有验收与决定，含扩面条件、触发和回退路径 |

## 负向场景：结构已定，仅一项定义争议

试用时判为 `establishing-data-governance` 主导：核对该定义的业务域 owner、相关利益方、既有决策授权、证据与备选定义、争议时限和升级规则，形成版本化决定并通知实施方。只有调查发现现有角色无授权或反复跨域冲突源于组织结构时，才触发本技能做组织调整。本场景不启动五模式比较、委员会重设或 10 周组织试点。此路由与 RED 基线同样正确，技能保留了边界。

## 缺陷判定与结论

- P0：无。
- P1：无。
- P2：无。技能已提供足够的判断准则和产物结构，使执行者在信息不足时能给出可审批的暂定模式、待取证内容、可计算容量和转换门，并正确处理负向路由。

GREEN 通过。仍须由实际项目确认现状、任命、工时、预算及 SLA；这些是场景缺失的业务输入，不是技能缺陷。评测中的样例数字和岗位均未冒充既有事实。

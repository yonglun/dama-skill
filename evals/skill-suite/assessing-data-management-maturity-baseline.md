# RED 基线：集团数据管理成熟度与预算

## 测试条件

- 在 `assessing-data-management-maturity` 技能创建前独立作答；未读取或使用该技能，也未修改任何技能。
- 场景：CEO 要求一周内给三个事业部组成的集团一个数据管理成熟度 1–5 分，用于下一年预算。各事业部的治理、质量、架构和元数据能力差异很大。现有材料只有自评问卷、制度文件和少量项目截图，没有现场运行样本。
- 以下“实际回答”先写，后续自评不回填到回答。

## 实际回答（未使用专属技能）

我会在一周内交付“预算决策用快速诊断”，但目前不能把自评问卷和制度存在性当作运行成熟度，也不能现在给出一个已核实的集团 1–5 分。先与 CEO 约定这周报告的用途：识别预算优先方向，正式的成熟度基线要在抽查实际运行证据后确认。若董事会材料必须出现单一数字，我会同时注明它是暂估、覆盖范围、证据限制和各事业部差异，避免把它当作精确排名。

第一天确定评估范围和评分口径。以三个事业部为行，以治理、数据质量、数据架构、元数据为列，记录每项能力是否有负责人、制度、执行流程、度量和改进记录。采用一个简单的五级尺度：1 为临时处理，2 为局部重复，3 为统一定义并执行，4 为有指标且持续控制，5 为持续优化。选每个事业部各一两个关键数据流程作为抽查对象，避免按材料厚度评分。

第二至三天整理问卷、制度和项目截图，逐项标出“自述”“文件可证”“运行可证”。访谈业务、数据负责人和一线执行者，追问近期一次数据问题、变更或审批如何发生、谁决定、留下什么记录。对无法展示的运行记录标为待验证，不用截图替代操作记录。

第四天做事业部 × 能力的初步评分卡，每格附主要证据、反例和信心等级。若只有问卷和制度，最多认定“已有定义”的迹象，不能证明稳定执行或持续优化。对高低差异明显的单元单独解释，不直接用平均分掩盖短板。集团整体可呈现分布、关键能力的最低水平和预算所依赖的风险；如确需单一数字，则作为有范围和置信说明的管理摘要，与矩阵同页展示。

第五天与各事业部核对事实，交付 CEO 一页决策摘要和证据附录：目前能够支持什么判断、哪些分数待现场核实、跨事业部共性问题、两三个下一年度投资包及其预期业务收益。预算建议优先处理有重大业务损失或审计风险、且能力缺口经多方证实的领域；再安排支撑共用标准和平台的投入。每个投资包明确负责人、成本级别、季度成果和可观察指标。建议预算启动后做一次正式抽样评估，并在半年后复评。

## 负向场景的实际回答

如果问题已经明确为“没有数据 owner，需要任命和决策流程”，应由数据治理工作主导。先定义数据域和决策权，提名并批准 owner，明确 steward 与业务/技术职责、争议升级路径和决策记录，再用真实问题验证流程是否运转。此时不需要为任命任务单独启动成熟度评估。

## 回答后自评：DMBOK 第 15 章维度遗漏

| 维度 | 实际回答覆盖 | 具体缺口 |
| --- | --- | --- |
| 范围 | 部分 | 列出了三事业部和四项能力，也选了流程抽样；没有说明为何仅选四项能力、哪些 DMBOK 知识领域和共用职能被排除、样本覆盖多少关键流程/系统，以及局部结果能否按统一准则形成集团结果。 |
| 框架选型 | 遗漏 | 自拟五级尺度，未比较现有成熟度框架在业务参与、行业适配、细度、可重复性、独立性和改进路径上的差异，也未说明裁剪框架时如何保留原模型含义。 |
| 证据强度 | 部分 | 区分了自述、文件和运行证据，也承认现有材料不足；但没有每条能力准则的证据台账、来源与日期、抽样母体、冲突证据处理或缺失证据导致的评分上限。 |
| 评分尺度与门槛 | 部分 | 只给五级粗定义，未把治理、质量、架构、元数据各级落实到可检查的活动和工作产品；没有准则级评分、层级晋升门槛、权重/汇总规则、`0=无能力` 或“不适用/不可判定”处理。单一集团数字虽被标为暂估，仍无可复算算法。 |
| 访谈、文件、运行三角验证 | 部分 | 提到访谈与运行记录追问，但没有正式安排按同一准则交叉核对问卷、文件、访谈和现场行为；现状没有运行样本，答复仍留下第四天给每格初评分的空间。 |
| 差异与不确定性 | 部分 | 要展示事业部差异和信心等级，却没有预设评分分歧的复核/共识会议、例外记录、未证实项与低分项的区分，也没有说明不确定性如何随集团摘要传播。 |
| 目标水平的业务理由 | 部分 | 提到预算收益和风险，但未为每个能力设定目标级别与需要达成的具体业务结果，也未分析从当前级到目标级的依赖、加速成本及不能跳级的约束。 |
| 改进组合优先级 | 部分 | 以风险与共用能力排序、提出两三个投资包；没有把评分缺口转为可排序的多年路线图，缺少机会价值、成本、依赖、可交付性与预期成熟度变化的共同评估。 |
| 复评节奏 | 部分 | 提了启动后正式抽样和半年复评；未发布固定复评日程、固定范围/准则/证据口径及变更条件，难以可靠比较趋势。 |

基线的主要失败模式是把“快速诊断”和可重复的成熟度评估混在一个五天方案里。虽然实际回答没有凭空给出集团分数，但所提初评分缺少框架选择、准则级门槛和可追溯的评分方法；在运行证据缺席时，预算可能仍依赖一个无法复核的暂估数。

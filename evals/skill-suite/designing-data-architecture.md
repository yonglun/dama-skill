# `designing-data-architecture` 独立 GREEN／边界评估

## 结论

测试 A 可由本技能作为主技能完成，且输出契约覆盖题目要求；已选云湖仓应被登记为不可改变约束与候选实现，而不是反向定义需求。测试 B 不应由本技能主导，应路由至 `modeling-data`。

## 测试 A：集团四周企业数据目标架构

### 任务书、范围与原则

**业务结果。** 在四周内交付可获批的企业数据目标、过渡架构和首批路线图，降低 40+ 系统点对点集成、语义不一致和无控复制带来的交付、质量及合规风险；支持交易、运营、分析及后续产品/AI 消费者。

**范围。** 企业级能力—数据关系、主题域/共同语义、权威来源、跨系统流向与血缘、复制、技术部署、生命周期及治理控制；覆盖现状、目标和首个过渡阶段。首期优先选取共享主/参考数据及其依赖的交易、分析能力。非范围是逐表逻辑/物理设计、单接口映射或 ETL 编排、备份/恢复容量方案。

**原则（均须可验证）。**

- 业务能力、事件和消费者驱动，需求与实现分离。
- 每个共享主题域明确业务数据管家、架构责任和权威源；共享术语、主数据与参考数据可追溯。
- 复制必须有目的，并声明源、延迟、新鲜度、质量、同步方式和退役条件。
- 流向、转换、消费者和跨境路径可追溯；敏感数据在物理落地前先解决位置、用途、访问、保留和保护约束。
- 目标、过渡、临时共存和退役均被显式描述；例外有批准、补偿、到期和复核。
- 在既定云湖仓内选择实现模式，但先以语义、服务、成本、地域、安全、质量和可演进需求检验其适配性。

### 现状证据与未知项

不将已有架构图视为事实。四周第 1 周以运行证据建立基线：CMDB/系统清单与责任人、接口和 API 配置、ETL/流作业定义、消息主题、数据库/存储清单、云配置、访问及审计日志、调度日志、数据质量结果、合同/跨境与隐私政策、成本及事故记录；访谈系统 owner、业务数据管家、安全、集成和平台团队。

将每条跨系统关系记录为：源、目标、传输/转换、频率与延迟、主题域/字段敏感级别、权威源、消费者、地域、责任人、证据链接和置信度。以此量化点对点接口、重复数据集、未具名权威源、定义冲突、批流混杂和未确认跨境路径。当前“跨境/敏感约束不清”是阻断物理落地的未知项，不以假设替代；在责任人确认前，将相关域标为受限并进入风险/决策清单。

### 需求

从能力—事件—消费者访谈和证据导出，而非从云产品导出：

- 功能/数据：主题域边界、核心业务事件、共同定义、权威源、允许的共享/消费方式、批流处理与消费场景。
- 质量/服务：关键数据完整性、准确性、新鲜度、可用性、峰值、延迟、对账和恢复目标。
- 控制：元数据、血缘、所有权、审计、访问控制、用途限制、地域、保留/处置及跨境要求。
- 经济与演进：成本边界、避免重复建设、可复用资产、迁移窗口、遗留共存期限与供应商/平台适配差距。

每项需求应有来源、优先级、验收证据和批准人；质量/创新目标分开记录。

### 视图目录

| 视图 | 要回答的问题 | 主要证据/验收 |
|---|---|---|
| 能力—数据（CRUD/事件） | 哪些能力产生、维护、使用哪些主题域，先后依赖是什么？ | 能力图、过程与访谈；业务和数据 owner 确认 |
| 概念主题域 | 企业共享什么语义，主题域边界和高层实体关系为何？ | 术语、数据清单、冲突定义；与后续模型可追溯 |
| 数据流/血缘 | 数据从哪里来、经过何种转换/复制、去往哪里，批流怎样共存？ | 配置、作业与日志；抽样链路核验 |
| 系统/应用责任 | 哪个系统是权威源、记录系统、消费者或复制节点？ | 系统清单和契约；责任人确认 |
| 技术部署 | 云湖仓中数据位于哪里、怎样处理和保护，地域是否合规？ | 云/基础设施配置及安全证据；关键约束闭环 |
| 生命周期/控制 | 创建至处置的所有权、质量、安全、保留和跨境控制是什么？ | 政策、控制与审计日志；数据管家/安全批准 |

每张图标明目的、范围、时间状态、图例、版本和负责人；跨视图名称和关系一致，且能支持一个真实决定。

### 目标与过渡架构

目标状态以主题域和权威源组织共享：业务事件经受控交换进入云湖仓的相应处理/存储/消费层；批、流按明确服务目标和血缘纳入同一语义与控制框架；元数据、术语、所有权、质量、访问、地域和生命周期控制贯穿流向。云湖仓可承载此实现，但并不自动成为每类数据、每种实时性或每个区域的答案。

过渡状态保留必要遗留系统和已有接口，建立受控的主题域共享路径与可观测复制；对每条临时双写、批流并存或点对点链路规定 owner、对账、延迟/质量门槛、风险补偿、退出触发条件与退役日期。不得在跨境、敏感分类、权威源或生命周期未决的主题域上批准物理落地。

### 关键 ADR

1. **ADR-01：已选云湖仓的适配与边界。** 比较“以其为统一实现”“保留域内系统并受控交换”“维持现状”对地域、敏感性、实时性、成本、恢复和可演进要求的证据；决定适用模式、差距、补偿和复核点，而非默认全量迁移。
2. **ADR-02：主题域权威源与有意复制。** 对每个优先主题域确定记录系统、主/参考数据发布责任、允许副本及同步/对账/SLO；否决无 owner 的复制。
3. **ADR-03：批流共存与服务分级。** 按事件/消费者延迟、可靠性和成本选择批、流或两者的过渡组合，规定幂等、顺序、迟到数据、对账与退役条件。
4. **ADR-04：敏感与跨境数据位置。** 由安全、隐私、业务 owner 基于分类、用途、地域、访问、保留和审计证据决定可处理/存储区域、脱敏/最小化及审批；未决即阻断。
5. **ADR-05：点对点退役模式。** 比较渐进封装/替换、短期保留和重建；选择按主题域依赖迁移，记录过渡成本和终止日期。

每项 ADR 都应包含状态/日期/决策人、候选方案（含维持现状）、比较证据、影响、风险补偿、后续动作及重新评估时点。

### 能力/数据依赖路线（四周交付 + 后续实施）

| 阶段 | 能力/依赖 | 工作包与出口证据 |
|---|---|---|
| 第 1 周 | 范围、系统/接口事实、约束 | 任务书获批；运行证据清单、未知项和风险登记；优先主题域候选 |
| 第 2 周 | 语义、权威源、能力—数据依赖 | CRUD/事件、主题域、系统责任和关键流向视图；owner 对关键事实确认 |
| 第 3 周 | 目标/过渡方案与关键控制 | 目标、技术部署、生命周期/控制视图；适配—差距矩阵；ADR 草案；跨境/敏感未决项升级 |
| 第 4 周 | 依赖排序、治理和首批验证 | 按主/参考数据→依赖交易→分析/产品能力排列的路线；首个工作包、退役清单、符合性门和验收包获批 |
| 实施波次 | 共享基础→消费者迁移→遗留退役 | 先发布受控主/参考能力和元数据/控制，再迁移依赖接口和消费，最后以对账与使用迁移证据退役临时链路 |

### 标准、符合性、风险与例外

将原则/标准置入项目立项、方案、概念/逻辑/物理模型、接口、采购、发布、技术更新和退役门。符合性记录至少列出项目/变更、适用原则、证据、符合/例外、风险与补偿、批准人、到期/复核；架构治理机构在授权范围批准重大决定和例外，具名企业数据架构师仍负责架构一致性。风险包括陈旧现状图、视图矛盾、无控复制、过度中心化、长期例外和按系统而非依赖排序；分别以运行证据、交叉视图检查、ADR、例外到期和运营反馈控制。

### 验收与指标

阶段门依次为：任务书/需求批准 → 现状与未知项核实 → 原则/方案/权衡批准 → 目标/过渡视图一致 → 首个工作包验证 → 项目符合与运营反馈。验收证据不是图的美观，而是视图一致、需求/证据可追溯、目标受众理解、可支持真实决策；关键跨境、安全、权威源或生命周期要求未决则不通过物理落地门。

基线并持续报告：适用项目评审参与率、标准符合率、例外及逾期数；复用/替换/退役比例、重复数据集和点对点接口数；设计/集成交付周期、返工、缺陷与成本；关键数据新鲜度、可靠性、质量、互操作、恢复、成本和安全事件趋势；能力上线、决策速度、分析/产品采用及利益相关者满意度。每项指标确定基线、目标值、数据源、频率和 owner。

## 测试 B：单一订单主题的表设计

**判定：边界外，路由至 `modeling-data` 为主技能。** 题目要求逻辑/物理表、键、属性、范式和命名，正是本技能明确排除的单一主题详细结构工作。本技能可在有跨系统影响时提供订单主题域边界、权威来源、生命周期、共享/复制及架构审查约束，但不应代替详细数据建模。若还要求接口、ETL 或流处理契约，另协同 `integrating-data`；若要求备份、容量或数据库运行，则协同 `operating-data-storage`。

## 覆盖性、边界与缺口评估

### 覆盖性（GREEN）

技能的触发条件、七步工作流和输出契约直接覆盖跨系统企业现状/目标/过渡架构。手册补足了任务书、证据导向现状核验、六类视图、ADR、能力/数据依赖路线、符合性记录、阶段门、角色、指标、风险和与相邻技能的边界。对“已选技术”特别明确为约束/候选实现，并要求适配—差距—补偿或升级决定，能避免厂商图取代架构。

### 边界清晰度

与 `modeling-data`、`integrating-data`、`operating-data-storage` 的主责划分清晰，也说明治理、元数据、质量、安全/伦理应协同而非被架构技能吞没。测试 B 能被明确拒绝为主任务，同时保留架构约束这一恰当的辅助角色。

### 缺口/可改进点

1. 输出契约未给出“四周快速架构”最小可交付集及每周时间盒；手册可增加一页快速路径，避免全量六视图在短周期被机械生产。
2. 虽要求场景/质量属性分析，但没有可直接填写的场景模板（峰值、故障、延迟、地域、审计、变更），使方案比较的证据粒度可能不一。
3. 跨境/敏感约束未决时的“阻断物理落地”已写明，但可进一步给出风险分级、升级 SLA 和临时数据最小化/隔离的标准例外字段。
4. 云湖仓适配要求充分，但缺少显式的产品/能力适配矩阵字段（如数据类型、延迟、地域、恢复、成本、锁定、运行责任）；附模板会让 ADR-01 更可复用。
5. 指标列举全面，未提供基线/目标/数据源/频率/owner 的指标表模板；实际验收时容易只报结果而缺少可持续量测定义。

这些缺口不妨碍测试 A 的 GREEN 结论，属于交付加速和可操作性增强，而非职责或方法缺失。

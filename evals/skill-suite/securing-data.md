# `securing-data` GREEN / 压力场景评估

评估对象：`skills/securing-data/SKILL.md` 与 `references/playbook.md`。

评估方法：用两个新场景检查应用能力、证据链和路由边界，不把文档覆盖等同于实际可执行性。

## 总结论

**GREEN。无 P0、无 P1。**

测试 A 能形成从现状冻结、分类与责任、最小权限、非生产脱敏、云/外包共同责任，
到负向测试、证据、阶段门和残余风险批准的可执行骨架。

测试 B 中，本技能明确承认“保护控制有效”不等于“用途公平或符合合理预期”，
应由 `handling-data-ethically` 主导，安全技能只负责保护性协同。

## 缺陷分级

### P0

- 无。

### P1

- 无。

### P2

1. **证据保管字段可更显式。**
   现有表已记录策略版本、主体、条件、实际日志、缺陷和复测；
   若增加证据库位置、哈希、采集时间、保留期和独立复核人，更利于长期审计。
2. **可增加整改台账最小模板。**
   建议标准化为“缺口、动作、Owner、依赖、截止日、阻断门、复测证据”；
   当前威胁表、阶段门和例外模板已足够执行，因此只是稳定输出形状的增强。
3. **脱敏攻击阈值可要求事前批准。**
   手册已要求组合重识别测试和批准风险阈值；
   可补充阈值必须在测试前由数据 Owner、隐私和安全共同确认，避免事后移动标准。

## 测试 A：零售客户与交易数据上云

### 场景

- 部门级粗角色；
- 生产数据进入开发测试；
- 共享服务账号；
- 外包运维；
- 无分类、审批、复核和可靠审计。

### 首要判定

**当前状态必须 No-Go，不能直接迁移或上线。**

技能明确把以下情形设为阶段门阻断项：

- 共享身份未收口；
- 生产数据无保护进入非生产；
- 关键日志缺失；
- 高风险负向测试失败；
- 供应商责任不明；
- 法律或伦理门未通过。

这能抵抗“云厂商已合规”“先上线再补控制”之类的常见错误推理。

### 1. 分类、范围与责任

技能要求先确定用途、数据、系统、地域、环境、供应商、风险容忍度和决策人。

| 对象 | 必填信息 | 阻断条件 |
|---|---|---|
| 客户/交易字段 | 来源去向、Owner、目的、分类、地域、环境、保留、允许动作 | 未知、无 Owner、无目的/保留结论则留在隔离区 |
| 人员身份 | 岗位、职责、地域、设备、审批、期限 | 共享人员身份禁止 |
| 工作负载 | 应用/作业、数据域、动作、环境、凭据、Owner | 身份必须唯一且不能交互登录 |
| 外包访问 | 具名人员、工单、时段、目标、会话证据 | 无共同责任或无 JIT/PAM 则不授权 |

决策权也清楚：数据 Owner 决定 entitlement；安全负责人可阻断安全门；
IAM/PAM、平台和工程负责实施；独立测试验证；供应商无企业风险接受权；
隐私、法务、合规和伦理保留各自的独立门。

### 2. 最小权限与共享账号整改

技能没有把部门角色直接当作最小权限，而是要求 entitlement 同时绑定：

- 数据域与分类；
- C/R/U/D、查询、导出、共享、管理、密钥等独立动作；
- 生产/非生产、地域、设备、时段；
- 目的、工单、批准人和到期日。

代表性整改链为：

1. 盘点部门角色、用户、服务账号与实际权限。
2. 数据 Owner 按职责和数据域定义目标矩阵，默认拒绝。
3. 读取不隐含导出；管理员不默认读取内容；密钥与数据读取职责分离。
4. 特权和外包改为具名身份、MFA、PAM/JIT、短期授权和自动到期。
5. 每个 ETL/API/BI 作业改用唯一托管身份或短期凭据。
6. 旧共享密钥轮换失效，服务身份禁止交互登录。
7. 调岗、离职、供应商换人和合同结束触发撤权；访问按风险复核。

因此，共享服务账号不只是“换强密码”，而是有清零、替换、失效和归责证据。

### 3. 非生产数据

技能给出的优先顺序可直接执行：

1. 合成数据；
2. 受约束生成数据；
3. 仅在必要且获批时使用最小生产子集；
4. 子集进入非生产前必须持久、不可逆脱敏。

它还明确：动态遮罩不能使保留原值的副本合格；
脱敏规则需覆盖直接标识、自由文本、组合重识别和跨表一致性；
脱敏失败不发布；数据集及下游副本到期删除；非生产不能访问生产或映射库。

这足以把现状转换为：冻结新增复制、盘点既有副本、隔离/删除、重建脱敏流水线、验证后再放行。

### 4. 云与外包共同责任

技能没有把责任转给云商或集成商，而是要求合同、技术控制、企业监控和审计权并行。

共同责任覆盖云配置、网络、密钥、环境隔离、供应商人员与设备、具名访问、
工单/PAM 会话、日志、事件协作、删除、分包商、退出迁移和证据提供。

企业数据 Owner 与控制 Owner 保留问责，外包商不能批准企业残余风险。

### 5. 负向测试与证据

| 代表性测试 | 预期 | 证据 |
|---|---|---|
| 跨角色/域/环境/地域访问 | 拒绝 | 策略版本、主体、条件、拒绝日志 |
| 普通读取者批量导出 | 拒绝 | 导出策略与 DLP/查询日志 |
| 撤权或离职后访问 | 立即失败 | 撤权事件、令牌失效、访问拒绝 |
| 服务身份交互登录、旧共享凭据 | 失败 | 身份策略、轮换记录、认证日志 |
| 外包 JIT 到期后访问 | 拒绝 | 工单、PAM 会话、自动撤权 |
| 管理员绕过内容策略 | 拒绝 | 管理和数据面日志 |
| 关闭关键日志 | 告警 | 日志完整性监控与事件工单 |
| 脱敏遗漏敏感字段 | 不发布 | 扫描、抽检、失败与复测记录 |
| 恢复副本访问 | 继承原控制 | 恢复演练、策略绑定、访问结果 |

证据表包含测试 ID、数据/策略版本、主体/条件/动作、预期、实际输出、结论、缺陷和复测批准；
“可重放、可归责”的要求能排除仅靠截图、口头确认或厂商证明的假验收。

### 6. 上线骨架

阶段门顺序为：范围/用途/Owner → 分类与风险 → entitlement/控制设计 → 实施与证据 →
允许/拒绝及事件演练 → 独立复核 → 分批上线和首次访问复核。

每批需携带残余风险、批准人和有期限例外；任一关键阻断项未关闭时留在前一阶段。

### 测试 A 结论

**通过。** 最小权限、脱敏、云/外包、负向测试与证据均能组合成可执行方案。

## 测试 B：忠诚度数据用于弱势群体差异化定价

### 主导技能判定

**`securing-data` 不应主导。**

数据已充分加密和限权，待决策的是新定价目的是否应该实施、是否对弱势群体造成不成比例影响、
是否符合客户合理预期，以及是否有伤害更小的替代方案。

这些是用途、尊重、公平、伤害、合理预期、解释和申诉问题，应由 **`handling-data-ethically` 主导**。

### 正确路由

1. `handling-data-ethically`：主导目的、受影响方、弱势群体、公平阈值、替代方案、申诉和停止条件。
2. 隐私/法务/合规：分别确认具体地区的法律依据、消费者保护、定价与歧视规则。
3. `establishing-data-governance`：明确批准、否决、例外和升级权。
4. `securing-data`：仅协同维护分类、最小权限、用途约束、日志和处理证据；未过并列门则技术阻断。

安全技能不得因为加密、限权、审计测试通过，就代替伦理判断或把保护性控制当作用途许可。

### 测试 B 结论

**通过。** 技能正文和手册均明确“控制与目的分离”，并把公平、合理预期和应否使用路由到伦理技能。

## 最终覆盖

| 评估项 | 结果 |
|---|---|
| 最小权限、唯一身份、审批/复核 | 通过 |
| 非生产最小化与不可逆脱敏 | 通过 |
| 云/外包共同责任与独立问责 | 通过 |
| 负向测试、可重放证据、事件接口 | 通过 |
| 阶段门、例外、残余风险 | 通过 |
| 公平与合理预期的边界路由 | 通过 |

**最终判定：GREEN。无 P0、无 P1；P2 均为非阻断表达增强。**

## 差异复核：P2 关闭状态

仅复核本轮三处补充，结论如下：

1. **证据保管字段：已关闭。**
   控制测试证据表已新增“证据位置/哈希/采集时间”和“保留期/独立复核人”，覆盖原建议且保持表结构可执行。
2. **整改台账模板：已关闭。**
   手册已新增独立模板，包含缺口/来源、风险/资产、整改动作、Owner/依赖、截止日、阻断阶段门、测试/复测证据及残余风险批准。
3. **脱敏攻击阈值事前批准：已关闭。**
   非生产数据方案已要求重识别方法、样本、成功定义和风险阈值在测试前由数据 Owner、隐私与安全共同批准，并明确禁止看到结果后移动标准。

**差异复核结论：三项 P2 全部关闭；未引入新的 P0、P1 或 P2，GREEN 维持。**

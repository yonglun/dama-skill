# 数据仓库与商业智能交付

## 核心原则

从业务要做的决定出发，追溯到问题、指标、维度、粒度、来源、转换、报告和行动。数据仓库整合并保存可分析的历史数据；BI 将数据交付给不同用户群。两者作为持续维护的数据产品，必须同时证明含义、质量、血缘、可用性和使用价值。

## 适用边界

- 跨来源分析、历史/同比、指标语义、维度模型、分析集市、仪表板、标准报表、评分卡和自助 BI 使用本技能。
- 单个 CDC/API/消息或文件管道，且不交付分析数据产品时，由 `integrating-data` 主导。
- 预测/分类模型、实验、特征与模型监控由 `delivering-data-science` 主导；本技能可提供可信分析数据和可视化。
- 通用数据库容量、备份和实例运行由 `operating-data-storage` 主导；本技能定义分析性能、刷新和数据产品服务要求。
- 业务术语/技术血缘的企业目录由 `managing-metadata` 主导；本技能必须给指标、数据集、报表提供可发现的定义与端到端血缘。
- 一次性探索图表且无持续发布、共享指标或服务承诺时，按轻量分析任务裁剪，不必建设仓库。

## 工作流

1. 明确决策者、决策频率、行动、问题与假设；把每个报表项关联到获批指标、维度、粒度和验收人。
2. 阅读[数据仓库与 BI 项目手册](references/playbook.md)，盘点用户群、来源、刷新、历史、质量、权限、数据时限、性能和已有资产。
3. 由业务 owner 裁决口径冲突；记录计算式、过滤、时间/币种/地区政策、版本、生效期、财务或监管对账要求和未决例外。
4. 选择仓库、集市、ODS、虚拟化或受控数据集的组合；先保留必要原子粒度和时间语境，再建设一致维度、汇总与语义层。
5. 设计源到分析数据的装载、拒收、迟到/更正、重跑、历史重述和分层对账；让业务对首装和多个更新周期的数据签收。
6. 按用户群交付报表/仪表板/自助能力；定义认证数据集、权限、可派生计算、导出、沙箱、推广与回收边界。
7. 分批发布，保留版本、回滚、变更影响、UAT 和服务接管证据；监控刷新、性能、质量、使用、满意度与业务行动。

## 输出契约

输出决策—问题—指标追溯；用户/场景与优先级；获批指标契约；来源画像和语义冲突记录；仓库/集市/语义架构；事实粒度、一致维度、历史与重述政策；装载/拒收/对账及业务验收；报告与自助权限边界；发布路线/回滚；SLA、支持、采用和满意度指标；阶段门、风险、例外和验收证据。

## 常见错误

| 错误 | 修正 |
|---|---|
| 从仪表板画面倒推指标 | 先记录决策、动作、指标定义和批准人 |
| 同名“收入”直接合并 | 区分销售、财务、未结/已结、退款、税费和汇率政策 |
| 先汇总后丢失明细 | 保留获准原子粒度、历史与控制总额，再按性能汇总 |
| 加载成功视为业务可用 | 源清单、分层对账、抽样、血缘和业务签收共同验收 |
| 自助 BI 等于任意重算 | 认证语义层、权限、派生计算边界与发布审批 |
| 上线即结束 | 运行刷新/性能/质量、支持、采用和满意度复盘 |

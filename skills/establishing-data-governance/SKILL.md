# 建立数据治理

## 核心原则

数据治理（Data Governance）行使对数据资产管理的权威、控制和共享决策；它确保数据被妥善管理，但不替代架构、质量、安全、主数据等团队执行管理工作。保持监督与执行的职责分离。

## 适用边界

- 需要明确“谁能决定、按什么原则决定、如何监督和升级”时使用本技能。
- 仅选择集中/联邦组织结构或设计岗位时，以 `organizing-data-management` 为主。
- 仅进行能力评分和差距分析时，以 `assessing-data-management-maturity` 为主。
- 只解决一个质量、架构或安全问题时，加载相应领域技能；治理负责所有权、标准、例外与监督。

## 工作流

1. 定义治理企业边界、数据域、决策类型、业务驱动和可衡量结果；不要从委员会图开始。
2. 评估现有决策、政策、协作、问题、质量、合规、文化和变更准备度；保留证据与未知项。
3. 读取 [治理运营手册](references/playbook.md)，建立章程、原则、运营框架、分层决策权和路线图。
4. 指定单一数据所有者以及执行、监督、咨询和消费角色；委员会不能代替最终负责者。
5. 建立政策—标准—流程—规则层级，议题/例外/合规流程，业务术语表和与项目、架构、审计、采购、开发生命周期的触点。
6. 以一个有业务价值的域或项目增量实施；同步沟通、培训、反馈和采纳。
7. 用业务结果、风险/质量改善、合规、决策时效和采纳衡量治理；定期调整而非把路线图冻结。

## 输出契约

输出治理范围与价值；原则；章程与层级；决策权矩阵；角色/责任；政策标准层级；议题/例外/合规流程；术语表治理；实施路线图；记分卡和嵌入计划。每项包含批准人、时限和验收证据。

## 常见错误

| 错误 | 修正 |
|---|---|
| 成立委员会即完成治理 | 验证决策、标准、问题和指标是否实际运行 |
| 数据办公室承担所有执行 | 业务与技术共享责任，领域团队执行，治理监督 |
| 先写政策再找价值 | 把每项治理能力关联业务结果、风险或合规需求 |
| 一次性企业全面推广 | 选择高价值范围，建立可复用机制后迭代扩展 |

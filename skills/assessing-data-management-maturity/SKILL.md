# 数据管理成熟度评估

## 核心原则

成熟度评估按明确框架和准则，检验流程是否被定义、实际执行、测量、控制并改进。评分必须绑定范围、证据和不确定性；结果服务于业务优先级与改进组合。文件存在、自评高分或一张截图不能证明持续运行。

## 适用边界

- 跨能力/事业部现状、证据分级、当前/目标级、差距、改进路线与复评使用本技能。
- 已知缺少数据 owner 而只需任命与决策机制，由 `establishing-data-governance` 主导实施；本技能仅在需要系统评估能力差距时介入。
- 数据管理组织结构设计由 `organizing-data-management` 主导；本技能提供能力/责任缺口证据。
- 单周快速诊断可报告观察、风险与待验证假设；没有足够运行证据时不得发布“已核实集团成熟度分数”。

## 工作流

1. 明确预算、监管、路线图或基线等评估目的；选择事业部、数据域、能力、流程与系统样本，写清排除与代表性。
2. 阅读[成熟度评估项目手册](references/playbook.md)，比较候选框架并批准版本、准则、裁剪、评分与汇总规则。
3. 对每条准则收集问卷、文件、访谈、现场运行/行为和反例；登记来源、日期、范围、抽样、证据强度与验证人。
4. 按等级逐级核查工作产品和持续行为；将“不适用”“未评估”“证据不足”和低成熟度分开，缺证据不推定为低分或高分。
5. 让评估人和业务/技术参与者校准分歧，保留不同意见；按事业部×能力报告等级、证据强度、覆盖与不确定性。
6. 若需要集团摘要，先验证预设权重、覆盖门槛与关键能力否决项；否则只报告分布、短板与风险，禁止伪精确均分。
7. 为每项目标级写业务结果、风险、前置能力、成本/收益和时间；形成排序改进组合、owner、阶段证据与复评日历。

## 交付模板

使用 [中文交付包](templates/delivery-pack.zh.md) 或 [English delivery pack](templates/delivery-pack.en.md) 组织输出。叙述性方案和评审记录使用同目录 Word 模板；矩阵、台账和评分卡使用同目录 Excel 模板。模板中的责任、阈值、批准和证据须由实际项目确认。

## 输出契约

输出目标/范围与抽样；框架选择/裁剪；准则级评分表和证据强度规则；访谈/文件/运行三角验证台账；现状矩阵及分歧/不确定性；集团摘要适用性与算法；目标级业务理由；改进组合/路线图；沟通、复评与验收证据。

## 常见错误

| 错误 | 修正 |
|---|---|
| CEO 要一个数就直接平均 | 先呈现事业部×能力分布、覆盖/证据；满足预设汇总门才给摘要 |
| 有政策文件即三级 | 检查实际执行与行为样本，文件只证明设计 |
| 无证据记零分 | 标“不可判定”，补证据；确证无能力才是 0 |
| 自拟五级不写准则 | 选/裁剪框架并保留逐级可观察门槛 |
| 只访谈管理者 | 文件、不同角色访谈、运行记录和反例三角验证 |
| 所有领域都追求五级 | 按业务风险、价值与成本设目标，遵守前置能力 |
| 评分完就结束 | 将差距映射到可交付改进、owner、指标与复评 |

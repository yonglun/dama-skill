# 数据项目通用交付模板

模板是输出契约，不是要求复制所有字段。删除不适用项时说明理由；未知项标为未决并指定所有者和日期。

## 1. 项目章程

```markdown
# <项目名称>
## 业务结果
- 要改善的决策/流程：
- 目标使用者与受影响方：
- 价值假设及验证方式：
## 范围
- 包含的数据域、系统、地域、时间：
- 明确排除：
- 重新纳入触发条件：
## 约束
- 法规/伦理/安全：
- 时间/预算/资源：
## 决策权
- 业务结果批准者：
- 数据所有者：
- 技术批准者：
- 风险/控制否决者：
## 完成证据
- 业务验收：
- 数据验收：
- 技术与运行验收：
- 控制与采纳验收：
```

## 2. 知识域工作包

| 字段 | 内容要求 |
|---|---|
| 知识域 | 主/基础/支持及选择理由 |
| 目标 | 与项目业务结果的直接关系 |
| 输入 | 已批准且可获得的前置工件/数据 |
| 活动 | Plan / Control / Develop / Operate 分类 |
| 责任 | 执行者、批准者、咨询者、消费者 |
| 交付物 | 具体可审阅的工件或运行能力 |
| 验收证据 | 查询、测试、签字、演练、趋势或运行记录 |
| 依赖 | 前置/后续工作包及接口 |
| 指标与阈值 | 结果、过程、质量和风险指标 |
| 裁剪 | 不做的活动、理由、风险所有者、触发条件 |

## 4. 决策权与 RACI

| 决策/工件 | Accountable（最终负责） | Responsible（执行） | Consulted | Informed | 时限 | 冲突升级 |
|---|---|---|---|---|---|---|

规则：每行只有一个最终负责角色；委员会不能代替未命名的负责人；涉及伦理、安全或监管否决权时单列。

## 5. 风险与控制登记册

| 风险事件 | 受影响结果/主体 | 原因 | 预防控制 | 侦测控制 | 纠正/回退 | 指标阈值 | 所有者 | 升级时限 | 剩余风险批准 |
|---|---|---|---|---|---|---|---|---|---|

不要只写“加强监控”。每个控制应有执行频率、证据位置、失败动作和责任人。

## 6. 阶段门记录

```markdown
## 阶段门：<名称> / <日期>
- 预期出口：
- 已提供证据：
- 未满足项及影响：
- 例外：风险、批准人、到期日、补救：
- 决定：Go / Conditional Go / Hold / Rework / Stop
- 决策人及理由：
- 下一门及所需证据：
```

## 7. 证据型成熟度评估

| 能力 | 当前实践 | 证据及日期 | 证据强度 | 当前能力结论 | 业务所需目标 | 差距影响 | 优先动作 | 负责人/期限 |
|---|---|---|---|---|---|---|---|---|

证据强度使用：`0 无证据`、`1 仅陈述`、`2 有文档/样例`、`3 有重复运行记录`、`4 有趋势与改进闭环`。能力结论不能高于证据能够支持的水平。

## 8. 完成审计

```markdown
- [ ] 业务结果有量化或可观察证据
- [ ] 所选知识域及裁剪理由完整
- [ ] 关键角色和决策权唯一明确
- [ ] 交付物均有验收证据
- [ ] 数据质量、元数据/血缘、安全/隐私/伦理已检查
- [ ] 运行、变更、采纳与退役责任明确
- [ ] 风险、阈值、升级和回退可执行
- [ ] 未决项有所有者和期限
```
